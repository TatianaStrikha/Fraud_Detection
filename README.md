# Система антифрода транзакций для онлайн-магазинов (MVP)

ИИ-сервис, который защищает малый бизнес от мошеннических оплат. Программа проверяет параметры платежа до того, как запрос уйдёт в банк.

Текущая демо-версия (MVP) сделана в виде платформы исторического тестирования. Загрузка файлов на сайте нужна специально для презентации: она имитирует поток покупателей и позволяет мгновенно проверить точность модели на архивных данных.

---

## Инструкция по быстрому запуску через Docker

### 1. Подготовка окружения
В корневом каталоге проекта находится файл конфигурации `.env.template`. Создайте на его основе рабочий файл `.env`.

### 2. Настройка количества распределенных воркеров
По умолчанию в файле `docker-compose.yml` задано 2 параллельных контейнера воркеров `ml_worker`.
Если вам необходимо изменить их количество (например 3), используйте флаг `--scale` при запуске:
```
docker compose up --build --scale ml_worker=3
```
*Для стандартного запуска с дефолтными настройками достаточно команды:*
```
docker compose up --build
```

## Пошаговый сценарий работы на демонстрационном сайте

После того как все контейнеры успешно запустились (`FastAPI`, `RabbitMQ`, `PostgreSQL`, `Nginx` и `ml_worker`), откройте в браузере адрес: http://localhost/.

Проверка ИИ-движка на дашборде проходит в **два этапа**:

### Этап 1: Пакетный скоринг транзакций (Имитация живого потока)
1. Нажмите на кнопку **«Выберите файл»** в первом блоке интерфейса и и загрузите файл с тестовыми транзакциями без готовых ответов — **`demo_test.csv`** из папки **`demo_data`**.
2. Нажмите кнопку **«Запустить проверку транзакций»**.
3. На экране появится прогресс-бар (от 0 до 100%). В этот момент асинхронный движок нарезает файл на батчи по 1000 строк, пушит задачи в RabbitMQ, а воркеры «вслепую» рассчитывают дельты времени карт по таблице `card_profiles`, генерируют фичи OpenFE и выносят вердикты CatBoost на основе порога `0.3422`.
4. По завершении ползунка система выведет общее число строк, а также количество Fraud и Legit транзакций.

### Этап 2: Ретроспективный аудит (Верификация точности ИИ)
1. Перейдите ко второму блоку интерфейса, нажмите кнопку **«Выберите файл»** и загрузите файл разметки — **`demo_target.csv`** из папки **`demo_data`**.
2. Нажмите кнопку **«Сохранить разметку в БД»**.
3. База данных PostgreSQL за миллисекунды сопоставит «слепые» вердикты CatBoost с исторической правдой.
4. Интерфейс обновится и выведет на дашборд готовую Матрицу ошибок.

## Технологический стек проекта
* **Backend:** FastAPI (асинхронная пакетная загрузка Highload-данных).
* **Broker:** RabbitMQ (распределение коротких команд-задач между воркерами).
* **Database:** PostgreSQL (буферная таблица `transactions` + накопительная память профилей карт `card_profiles`).
* **ML-Engine:** CatBoost Classifier (векторный инференс, выравнивание до 111 признаков, учет формул OpenFE).
* **Gateway:** Nginx (сетевой шлюз, проброс реальных IP-адресов, лимит на размер body до 200Мб).
* **Environment:** Docker / Docker Compose (полная изоляция и независимость микросервиса).

## Результаты Feature Engineering и Метрики
В ходе итерационной разработки и проведения экспериментов на валидационной выборке, модель показала стабильный рост качества:
* **Пик точности ИИ (Валидация):** Метрика **PR-AUC: 60.80%** | Полнота (Recall при FPR 1%): **51.38%** (при рабочем пороге отсечения `0.3422`).
* **Боевой замер на отложенном тесте:** **PR-AUC: 50.11%** | Полнота: **42.13%**. Естественное падение метрик на данных из будущего наглядно подтвердило главный продуктовый риск — изменение паттернов поведения мошенников (**Data Drift**).
