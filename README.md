# Система антифрода транзакций для онлайн-магазинов (Дипломный проект)

ML-сервис, который защищает малый бизнес от мошеннических оплат. Программа проверяет параметры платежа.

Текущая демо-версия (MVP) сделана в виде платформы исторического тестирования. Загрузка файлов на сайте нужна специально для презентации: она имитирует поток покупателей и позволяет мгновенно проверить точность модели на архивных данных.

## Инструкция по быстрому запуску через Docker

### 1. Подготовка окружения
В корневом каталоге проекта находится файл конфигурации `.env.template`. Создайте на его основе рабочий файл `.env`.

### 2. Настройка количества распределенных воркеров
По умолчанию в файле `docker-compose.yml` задано 2 параллельных контейнера воркеров `ml_worker`.
Если вам необходимо изменить их количество (например 3), используйте флаг `--scale` при запуске:
```
docker compose up --build --scale ml_worker=3
```
*Для стандартного запуска с дефолтными настройками достаточно команды:*
```
docker compose up --build
```

## Пошаговый сценарий работы на демонстрационном сайте

После того как все контейнеры успешно запустились (`FastAPI`, `RabbitMQ`, `PostgreSQL`, `Nginx` и `ml_worker`), откройте в браузере адрес: http://localhost/.

Проверка ИИ-проходит проходит в **два этапа**:

### Этап 1: Пакетный скоринг транзакций (Имитация живого потока)
1. Нажмите на кнопку **«Выберите файл»** в первом блоке интерфейса и и загрузите файл с тестовыми транзакциями без готовых ответов — **`demo_test.csv`** из папки **`demo_data`**.
2. Нажмите кнопку **«Запустить проверку транзакций»**.
3. На экране появится прогресс-бар (от 0 до 100%). В этот момент асинхронный движок нарезает файл на батчи по 1000 строк, пушит задачи в RabbitMQ, а воркеры рассчитывают дельты времени карт по таблице `card_profiles`, генерируют фичи OpenFE и выносят вердикты CatBoost на основе порога `0.3422`.
4. По завершении ползунка система выведет общее число строк, а также количество Fraud и Legit транзакций.

### Этап 2: Ретроспективный аудит (Верификация точности ИИ)
1. Перейдите ко второму блоку интерфейса, нажмите кнопку **«Выберите файл»** и загрузите файл разметки — **`demo_target.csv`** из папки **`demo_data`**.
2. Нажмите кнопку **«Сохранить разметку в БД»**.
3. База данных PostgreSQL сопоставит вердикты CatBoost с исторической правдой.
4. Интерфейс обновится и выведет на дашборд готовую Матрицу ошибок.  

Кнопка **«Сбросить демо-данные»** полностью очищает базу данных от загруженных ранее файлов.

## Технологический стек проекта
* **Backend:** FastAPI — асинхронный веб-сервер. Принимает файлы на сайте и нарезает их на батчи по 1000 строк для быстрой обработки.
* **Broker:** RabbitMQ — брокер очередей. Распределяет батчи по воркерами.
* **Database:** PostgreSQL — база данных. Хранит информацию в двух таблицах: `transactions` (буфер для транзакций со статусом обработки) и `card_profiles` (накопительная память карт для расчёта дельты времени между покупками).
* **ML-Engine:** CatBoost Classifier — модель. Работает внутри воркеров. Перед запуском модели воркер сначала преобразовавает ячееки в необходимий формат. Затем, по шаблону из файла `artifacts.pkl`, собирает итоговую таблицу из 111 признаков (куда входят отобранные базовые колонки из исходного 400+ датасета, 10 формул OpenFE и 1 рассчитанный признак дельты времени `time_diff_card_uid`) и выдаёт вердикт.
* **Gateway:** Nginx — сетевой шлюз и прокси-сервер. Позволяет заходить на сайт по стандартному адресу `http://localhost/`, защищает систему от перегрузки тяжелыми файлами (лимит до 200 Мб) и передаёт реальные IP-адреса пользователей внутрь бэкенда.
* **Environment:** Docker / Docker Compose — среда контейнеризации. Упаковывает каждый компонент в изолированную коробку, гарантируя независимость микросервисов, стабильную связь между ними и запуск проекта на любом компьютере.

## Результаты Feature Engineering и метрики
В ходе итерационной разработки и проведения экспериментов на валидационной выборке, модель CatBoostClassifier показала стабильный рост качества:
* **Пик точности ИИ (Валидация):** Метрика **PR-AUC: 60.80%** | Полнота (Recall при FPR 1%): **51.38%** (при рабочем пороге отсечения `0.3422`).
* **Замер на отложенном тесте:** **PR-AUC: 50.11%** | Полнота: **42.13%**. Естественное падение метрик на данных из будущего наглядно подтвердило главный продуктовый риск — изменение паттернов поведения мошенников (**Data Drift**).
