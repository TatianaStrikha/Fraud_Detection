# Проект: Система антифрода транзакций для онлайн-магазинов

---
# Прототип продукта

## 1. Ключевая гипотеза
**Если мы предлагаем** систему автоматизированного скоринга транзакций **для** владельцов и риск-менеджеров малых и средних онлайн-магазинов в сфере e-commerce  **в сценарии** проверки онлайн-платежей по картам, **то мы получим** значение метрики PR-AUC не меньше 0.60 **в течение** первого месяца тестовой эксплуатации,
**потому что** алгоритмы градиентного бустинга эффективнее классических правил находят скрытые зависимости в поведении мошенников при сильном дисбалансе данных.

---

## 2. Ключевые метрики


| Категория | Метрика | Целевое значение | Способ измерения | Baseline           | Частота |
| :--- | :--- |:-----------------| :--- |:-------------------| :--- |
| **Техническая** | **PR-AUC** | > 0.60           | Оценка на валидационной выборке (Precision-Recall Curve) | 0.035 (доля фрода) | При каждом обучении |
| **Техническая** | **Inference Time** | < 200 мс         | Время ответа модели на один запрос (API) | 500 мс             | При нагрузочном тесте |
| **Продуктовая** | **False Positive Rate (FPR)** | 0,1-0,5%        | Доля ложных блокировок среди всех честных транзакций | 1%                 | Еженедельно |


---

## 3. Состав прототипа

*   **Что входит:**
    *   Датасет [IEEE-CIS Fraud Detection (Kaggle)](https://www.kaggle.com/competitions/ieee-fraud-detection/overview), так как модель делает предсказание, в том числе на основании исторических данных.
    *   Обученная модель (CatBoost) с оптимизацией под дисбаланс классов.
    *   Демонстрационный эндпоинт (подробнее в блоке *6. Вид прототипа*)
*   **Что намеренно не делаем:**
    *  Дообучение модели, прототип работает на исторических данных.
    *  Логирование.

---

## 4. Блоки и инструменты

*   **Готовые блоки:**
    *   Scikit-learn / CatBoost: Библиотеки для реализации алгоритмов машинного обучения.
    *   FastAPI: Создание легковесного сервиса для обработки запросов.
    *   Датасет IEEE-CIS Fraud Detection (Kaggle).
*   **Собственная разработка (Критично):**
    *   Пайплайн инженерии признаков (Feature Engineering): логика обработки анонимизированных данных. Это критично, так как именно качество признаков определяет успех модели в антифроде.

---

## 5. Главный риск, проверяемый прототипом
**Риск низкой предсказательной способности:** Существует вероятность, что из-за анонимизации данных и отсутствия прямого доступа к смыслу переменных, не удастся выявить устойчивые зависимости.

**Цель проверки прототипом:** Подтвердить, что имеющегося набора признаков достаточно для обучения модели с показателем PR-AUC > 0.60 и FPR < 0,5%. 


---

## 6. Вид прототипа

1.  **Слой аналитики:**
    *   **Задача:** Обучение модели, расчет метрик, проверка гипотез. 
    *   **Инструмент:** Jupyter Notebook / Python скрипты. 
    *   **Результат:** Сохраненный файл модели.  


2.  **Интерфейсный слой (демо API-эндпоинт).**   
    Вместо ручного ввода параметров, механизм взаимодействия через отложенную выборку:
    *   **Запрос списка:** Эндпоинт предоставляет перечень доступных ID транзакций.
        *   **Источник данных:** отложенная выборка, которая не участвовала в обучении и тестировании.
        *   **Препроцессинг:** Данные в списке уже приведены к финальному формату, необходимому для модели. 
    *   **Выбор транзакции:** Пользователь выбирает конкретный ID из предложенного перечня.
    *   **Автозаполнение:** Система извлекает полный набор признаков для выбранного ID.
    *   **Вердикт:** Модель проводит скоринг и возвращает итоговое решение.


---

## 7. Критерии остановки теста
**Тест проводится в течение месяца.**

**Результаты теста:**
* **Тест признается успешным**, если достигнуты целевые метрики: модель стабильно показывает PR-AUC>0.60 и FPR < 0,5%.
* **Тест признается неудачным**, если целевые метрики не достигнуты.

**Тест признается неудачным и останавливается досрочно**, при значительном отклонении хотя бы одной из метрик в худшую сторону:
- **PR-AUC< 0.40**: модель недостаточно эффективно разделяет классы в условиях дисбаланса.
- **FPR > 5%**: модель создаёт недопустимую нагрузку на лояльных клиентов и службу поддержки.
